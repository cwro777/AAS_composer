BaSyx 연동 노트

AAS Composer가 만든 모델을 다른 시스템이 표준 API로 읽어 갈 수 있게 올려 두는 서버가 BaSyx입니다. 무엇을 쓰고 있고, 어떻게 올리며, 실제로 올라가는지, 그리고 더 만들어야 할 것이 무엇인지 정리합니다.

개발 대상 아님

BaSyx 자체는 만들지 않습니다. Eclipse 재단의 오픈소스 AAS 서버를 컨테이너 그대로 띄워 씁니다. 우리가 만드는 것은 BaSyx에 모델을 올리는 게시 게이트웨이이고, 그것은 이미 있으며 실제 서버에서 동작을 확인했습니다.

남은 것은 BaSyx를 개발하는 일이 아니라 연결을 채우는 일이었습니다. 2026-09-27에 셋을 채웠습니다 — 에디터의 BaSyx에 게시 버튼, 개념 설명(단위·정의) 게시, mock 정의 제외. 나머지는 아래 "남은 것"에 크기와 필요한 시점을 적었습니다.

무엇인가

BaSyx와 AAS Composer의 역할

AAS Composer — 저작 원본

  • 모델을 만들고 고치는 곳 · 모든 변경이 명령 로그와 버전으로 남음
  • 네 계층 검증 · 템플릿 적합성 · 용어집과 개념 등록
  • 설비 값 수집(MQTT·OPC UA)과 시계열 · 운전 화면
  • 구조의 원본 — 수집 값을 여기에 되쓰지 않음

BaSyx — 게시된 사본

  • AAS V3 표준 API로 셸·서브모델을 내주는 서버
  • MES·대시보드·타사 도구가 표준 경로로 읽어 가는 곳
  • 버전·검증·용어집은 없음 — 받은 것을 저장하고 내줌
  • 실행 중 값의 런타임 사본이 될 자리(값 갱신은 아직 꽂지 않음)

게시 대상은 BaSyx V2(AAS V3 API) 하나로 P0에서 확정했습니다. 버전 어댑터를 만들지 않습니다.

열람 화면 — http://localhost:8082

BaSyx가 만든 화면(aas-gui)을 compose에 넣었습니다. 개발자가 아닌 사람에게 보여 줄 때 씁니다 — 셸을 고르면 서브모델 트리가 열리고, 요소를 누르면 값·semanticId·JSON을 봅니다.

레지스트리 없이 붙는다

저장소 주소를 직접 줍니다(AAS_REPO_PATH · SUBMODEL_REPO_PATH · CD_REPO_PATH). 이 주소는 브라우저가 부르므로 컨테이너 이름이 아니라 호스트에서 보이는 주소여야 합니다 — 다른 PC에서 열려면 localhost를 이 PC의 IP로 바꿔 띄웁니다.

CORS를 함께 켰다

화면이 브라우저에서 BaSyx를 직접 부르므로 BASYX_CORS_ALLOWED-ORIGINS가 없으면 목록이 빈 채로만 보입니다(원인은 콘솔에만 남습니다). 개발용으로 열어 두었으니 사내망 밖으로 열 때는 좁히십시오.

주의: 이 화면은 편집·업로드도 허용되어 있고 인증이 없습니다. 보여 주기 전용으로만 쓰십시오. 컨테이너 안 nginx는 3000으로 듣습니다 — 이미지의 EXPOSE(80)와 어긋나므로 그 값을 믿고 매핑하면 연결이 끊깁니다.

mock 정책 — 2026-09-27

지어낸 정의는 올리지 않는다

개발·시연을 위해 사전에는 mock이 들어 있습니다 — eCl@ss 후보(라이선스를 가정한 것)와 아무도 발행하지 않은 IRI의 정의입니다. mock 파일이 스스로 "Do not ship"이라고 적습니다. 그런데 그것이 BaSyx에 올라가 있었습니다.

게시에서 뺀다

사전이 mock으로 답한 개념은 싣지 않고, 무엇을 뺐는지 mock으로 돌려줍니다. 에디터 알림도 "mock 정의 N건은 빼고 올렸습니다"라고 말합니다. 샘플이 같은 개념을 제대로 알면 그것으로 나갑니다.

표시가 덮이지 않게

에디터가 모델을 보내며 개념을 사전에 넣을 때 mock 항목의 출처가 editor:…로 덮여, 지어낸 정의가 보통 항목처럼 보였습니다. 이제 에디터는 mock을 보내지 않고, 사전도 이미 mock인 항목의 출처를 덮지 않습니다.

주의: 게시는 올리기만 합니다. 이미 올라간 mock은 따로 지워야 합니다 — 이번에 10건을 지웠습니다.

개발 여부

남은 것 — BaSyx가 아니라 연결

했음
개념 설명(ConceptDescription) 게시

게시가 serialize(doc)만 보내 BaSyx에는 0건이었습니다. 이제 서버가 buildServerExport로 개념을 만들어 /concept-descriptions에 먼저 올립니다. 서버는 브라우저 용어집을 모르므로 에디터가 서버에 보내기에서 용어집을 사전에 함께 넣습니다. 사전도 샘플도 모르는 개념은 지어내지 않고 unresolved로 돌려줍니다.

2026-09-27
했음
에디터의 게시 버튼

파일 메뉴의 BaSyx에 게시. 서버에 없는 모델이면 먼저 보내고, 결과를 한 줄로 알립니다 — 올린 건수·개념 수·실패 항목·사전이 모르는 개념. 검증 오류(422)는 확인 창에서 사람이 강행을 결정하고, BaSyx가 없으면(502) 띄우는 방법을 안내합니다.

2026-09-27
했음
mock 정의를 게시에서 제외

사전이 mock으로 답한 개념은 싣지 않고 mock으로 돌려줍니다. 에디터는 mock을 사전에 보내지 않고, 사전은 이미 mock인 항목의 출처를 덮지 않습니다 — 한 번 editor:…로 덮여 걸러낼 근거가 사라졌습니다. 이미 올라가 있던 10건은 BaSyx에서 지웠습니다.

2026-09-27
설정
저장 방식 — InMemory

컨테이너를 다시 띄우면 게시한 모델이 사라집니다. 운영에서는 영속 백엔드로 바꿔야 합니다. BaSyx 쪽 설정 문제이며 우리 코드는 바뀌지 않습니다(BaSyx 문서 기준 — 이 프로젝트에서 아직 시험하지 않음).

설정 · 운영 전 필수
없음
지운 것 동기화

게시는 올리기(POST/PUT)만 합니다. 에디터에서 서브모델을 지워도 BaSyx에는 남습니다. 무엇을 지울지 미리 보이고 확인받는 방식이어야 합니다(계획과 적용 분리).

대기

patchValue()는 만들어 두었지만 꽂지 않았습니다. 수집한 신호를 어느 요소에 쓸지는 AID가 말해 주지 않고 IDTA 02027(AIMC)의 몫이라, 짐작으로 잇지 않습니다.
