AAS Composer 총람

산업 설비를 AAS 모델로 만들고, 네 계층으로 검증하고, BaSyx V2에 게시하고, 설비 값을 받아 운전 화면에 보이는 웹 플랫폼입니다. 이 문서는 지금까지 만든 것 전체를 한자리에 정리합니다 — 무엇이 있고, 어떻게 연결되며, 어떤 원칙으로 판단하는지.

검증

규격(aas-core3.0) · 사내 정책 · 템플릿 적합성 · 사전(개념) 네 계층. 고칠 수 있는 이슈에는 버튼이 붙습니다.

서버에 모델과 명령 로그를 남기고, 버전 비교(diff)와 서버 검증을 합니다. 에디터는 브라우저에 자동 저장합니다.

내보내기 · 게시

AAS Environment JSON과 AASX(OPC 패키지)로 내보내고, BaSyx V2(AAS V3 API)에 게시합니다.

값 수집 · 운전

AID 서브모델을 설정으로 읽어 MQTT·OPC UA에서 값을 받고, 운전 화면에 수집 상태·신호 지연·시계열을 보입니다.

값 수집 · 운전 모니터링

AID가 곧 설정

planFor(doc)가 AID 서브모델에서 프로토콜·주소·신호를 읽고, 읽지 못한 것은 problems에 남깁니다. 조용히 넘기지 않습니다.

MQTT

숫자로 읽히지 않는 페이로드는 textValue로 — 0으로 바꾸지 않습니다. 연결 대기 타이머를 반드시 지우고, 붙은 뒤의 'error'도 듣습니다(안 들으면 API가 죽고, 안 지우면 8초마다 값이 조용히 멎었습니다).

OPC UA

폴링이 아니라 구독. AID의 browsePath를 TranslateBrowsePathsToNodeIds로 한 번 옮긴 뒤 감시합니다. Bad 상태는 값이 아니라 problems로. 보안은 None · 익명만.

되쓰지 않는다

수집한 값을 저작 문서에 쓰지 않습니다 — 버전 비교가 무의미해집니다. 신호 → 요소 연결은 IDTA 02027(AIMC)의 몫이라 짐작하지 않습니다.

운전 화면

수집 상태 · 신호별 지연 · 시계열. 지연은 서버가 준 now로 잽니다. 값이 온 적 없는 신호도 목록에 남고, 서버 없음 · 모델 없음 · 수집 꺼짐을 다른 화면으로 안내합니다.

확정된 원칙

  • 문서 변경은 반드시 Cmd를 거친다 — 실행취소 · 버전 · 감사 추적이 여기서 나옵니다.
  • semanticId를 추측하지 않는다 — 레지스트리에서 가져오거나, 확인 못 한 값은 verified: none으로 남겨 보고합니다.
  • 표준 식별자는 한 글자도 바꾸지 않고, 우리 개념은 우리 이름으로 — {ns}/cd/…로 발행하고 뜻을 채웁니다.
  • 식별자를 바꿀 때는 참조를 함께 — renameIdentifier()가 문서 전체의 Reference 키를 하나의 batch로 고칩니다. raw는 문자열 치환하지 않고 알립니다.
  • 계획과 적용을 분리한다 — 마이그레이션 · 서브모델 합치기 · 네임스페이스 옮기기는 무엇이 바뀌는지 먼저 보입니다.
  • 있는 척하지 않는다 — 어댑터가 없는 프로토콜, 상류가 없는 사전, 대조 못 한 eCl@ss는 없다고 말합니다.
  • 오류는 판별 가능한 코드로, 메시지는 { ko, en } 두 벌. 색은 CSS 변수로만.
  • 파생값은 저장하지 않는다 — JSON 미리보기와 검증 이슈는 selector로 계산합니다. 서버 상태는 TanStack Query, 에디터는 Zustand, 섞지 않습니다.
